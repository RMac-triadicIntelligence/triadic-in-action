2. New findings
F20 Section: §5.6, §1.2, §1.5 Concrete failure: Rule 1 requires deposits at authorized crossings. §5.6 simultaneously requires deposits only after retrospective confirmation and states that an oscillating candidate produces no J_F deposit, yet also says “retain \ldots any already committed authorized deposit.” The two rules conflict. An implementer who commits on authorization writes an unconfirmed deposit; one who waits writes nothing. Descendants then inherit different J_F snapshots for the same crossing sequence. Severity: FATAL Minimal fix: Choose one rule and delete the other. Either deposits are written only after confirmed persistence (and “already committed” language is removed) or they are written on authorization and later corrected by an explicit δ_F that references the error. Source: DOC
F21 Section: Appendix A, §5.7 Concrete failure: The golden trace overrides z₀ to (256,128), uses NONE encounters, zero holds, empty J, and never crosses. It therefore never exercises U’s outer-product term, E accumulation, dwell reset of W, gate staging, oscillation, UNKNOWN_CROSSING, or J append. Two implementations can match the trace bit-for-bit and still diverge on every path that involves a real Encounter or a candidate crossing. Severity: WOUNDING Minimal fix: Supply additional normative traces that include at least one non-zero Encounter, one hold sequence, one zero-touch, and one oscillation, and require bit-identical match on those as well. Source: DOC
F22 Section: §5.1, §5.4, §5.6 Concrete failure: Φ is defined to take J_F. The toy update rules in §5.4 never read J_F; M is computed from D, P₀, E, T, z only. An implementer following the general equation includes J; one following the toy equations ignores it. When a deposit later occurs, the two traces diverge even though both claim to implement the reference. Severity: WOUNDING Minimal fix: Either remove J_F from the toy’s Φ or supply the exact fixed-point formula by which the current J tip contributes to M. Source: DOC
F23 Section: §2.8, §5.6 Concrete failure: The protocol stages a candidate, reserves a nonce, obtains witness commit, then performs compare-and-swap. For crossings the gate must check before commit, yet confirmation requires two further learning steps after the candidate. If those two steps are ordinary U updates that themselves alter z and T, the pre-state hash used for the original authorization no longer matches the state at confirmation time. The CAS then fails or, if the hash is not re-checked, an effect is applied against a stale authorization. Severity: FATAL Minimal fix: Freeze the candidate state (or re-authorize against the post-persistence state under the same Permit) before the final append of δ_F; document the exact hash that is compared at each stage. Source: DOC
F24 Section: §1.3, §5.1, H3 Concrete failure: Descendants inherit a snapshot of J_F. Φ may read J_F. Nothing prevents a parent from inducing a sequence of authorized crossings whose deposits encode a high-entropy pattern that later functions as a shared seed. The E2 “non-epistemic perturbation” control does not cover deposits written after birth. Family classification then succeeds because of the inherited J pattern rather than developmental topography. Severity: WOUNDING Minimal fix: Require J-shuffled and J-empty arms to be run on the identical sequence of crossing points, and treat any residual family signal after shuffling as contamination. Source: DOC
F25 Section: §5.2 Concrete failure: Canonical encoding requires “fixed field IDs and declared inclusion rules” and domain-separated CBOR, yet no concrete field-ID assignment, map key integers, or inclusion bitmap is given. Two implementers can choose different integer keys or different orders for optional NONE fields and produce different SHA-256 hashes for logically identical states. H4 hash checks then fail spuriously or, worse, accept a colliding encoding. Severity: WOUNDING Minimal fix: Publish the exact integer key map, the byte layout of every field, and at least three canonical test vectors (including one with NONE and one with a non-empty J) before any scored run. Source: DOC
F26 Section: §6 H1, E1, E3 Concrete failure: H1 requires T to outperform an equally sized conventional state on targets “generated independently of the T reference model.” No generator is specified. An experimenter can choose a target process whose sufficient statistics happen to be low-rank outer products of the same form as U. T then wins for a reason unrelated to relational topography. Severity: MINOR Minimal fix: Freeze the target-generating process (or an explicit list of admissible processes) in the preregistration manifest and require that it not be definable by the same outer-product update. Source: DOC
F27 Section: §2.4, §2.5 Concrete failure: PA signers “cannot be reciprocal organism-family voting rings.” The check is described only as “disclosed controlling-party and benefit relationships.” Nothing defines the algorithm that detects a cycle or a mutual-benefit edge. Two families can still exchange PA roles through an undeclared intermediary institution that both control. Severity: MINOR Minimal fix: Require an explicit, auditable approval-graph cycle check at accreditation time and include a cross-family ring test in E6 that must fail closed. Source: DOC
3. Single finding to fix first F20 (conflicting deposit rules for unconfirmed crossings). Until the specification states a single, non-contradictory rule for when δ_F is appended, every claim about inherited lineage ground and H3 is implementation-dependent.
Blue-sky idea the designer missed (not scored) Record every pure-hold interval as an immutable, non-epistemic scheduler trace that is hashed into the audit log but is invisible to Φ, U, and J_F. Later analysis can then measure whether organisms that receive identical learning-step sequences but different hold traces develop distinguishable private T, turning the residual real-world timing channel into a quantifiable covariate rather than an unmodeled side-effect.
